# Data

## Source

**Electric Vehicle Charging Patterns** by Vala Khorasani, on Kaggle:
<https://www.kaggle.com/datasets/valakhorasani/electric-vehicle-charging-patterns>

Downloaded and committed unmodified as `raw/ev_charging_patterns.csv`. Refer to the
Kaggle dataset page for its license and terms of use. It is **synthetic** — published
for practising machine-learning workflows, **not** a reliable source for research or
publication.

## `raw/ev_charging_patterns.csv`

**1,320 EV charging sessions**, 20 columns, spanning 2024-01-01 to 2024-02-24.

| Column | Meaning |
| --- | --- |
| User ID | Unique id per user. Every row has a different one — one session per user. |
| Vehicle Model | One of 5: Tesla Model 3, Hyundai Kona, Nissan Leaf, BMW i3, Chevy Bolt. |
| Battery Capacity (kWh) | Vehicle battery size. Contains implausible values (min 1.5, max 193). |
| Charging Station ID | 462 distinct stations — ~2.8 sessions each. |
| Charging Station Location | One of 5 cities: New York, Los Angeles, San Francisco, Houston, Chicago. |
| Charging Start Time / End Time | Session timestamps. Start is always on the hour. |
| Energy Consumed (kWh) | Energy delivered. **66 missing.** 190 rows exceed battery capacity. |
| Charging Duration (hours) | Reported duration. Disagrees with End − Start by ~1.2 h on average. |
| Charging Rate (kW) | Average power. **66 missing.** |
| Charging Cost (USD) | Session cost. |
| Time of Day | Morning / Afternoon / Evening / Night. Does **not** match the timestamp hour. |
| Day of Week | Weekday name. Does **not** match the timestamp date. |
| State of Charge (Start %) / (End %) | Battery %, start and end. 32 rows fall outside 0–100; 268 rows do not increase. |
| Distance Driven (since last charge) (km) | **66 missing.** |
| Temperature (°C) | Ambient temperature. The `°` is a Latin-1 `0xB0` byte in the header. |
| Vehicle Age (years) | 0 to ~12. |
| Charger Type | Level 1 / Level 2 / DC Fast Charger. |
| User Type | Commuter / Casual Driver / Long-Distance Traveler. |

## `processed/`

Regenerated by the pipeline scripts. Not committed.

- `sessions_clean.parquet` — all 1,320 rows with canonical column names, engineered
  features, and per-row validation flags. Downstream steps filter this per task.
  (`python scripts/prepare_data.py`)
- `validation_report.json` — counts and percentages for every data-quality rule.
  (`python scripts/prepare_data.py`)
- `analytics.json` — the precomputed dashboard payload: overview KPIs, time/location/
  segment breakdowns and an anomaly summary. (`python scripts/build_analytics.py`, or
  `train_all.py` which also refreshes it)

## Known data-quality issues (summary)

This dataset was generated column-by-column with little cross-column consistency. The
validation layer measures the damage rather than trying to repair it:

- Reported `Charging Duration` is essentially independent of `End − Start`.
- `Charging Rate × Duration` rarely matches `Energy Consumed`.
- `Energy Consumed` can exceed `Battery Capacity`.
- `State of Charge` can decrease during a session or leave the 0–100 range.
- `Time of Day` and `Day of Week` are uncorrelated with the actual timestamps.

These caps on internal consistency also cap how well any model can fit. That limitation
is stated explicitly in the notebooks and the final README.
